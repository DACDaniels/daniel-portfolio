## 2026-11-01: Iris simulation, sample chat replay, testimonials

- **"See how Iris thinks" on /projects/fishtech.** Five stages (Species, Measure, Weigh, Pond biomass, Feed) run on a TypeScript port of the Iris code (src/lib/iris-sim/model.ts), read only from fishtech-precision-feeding-system at commit e624125 (main, 2026-08-14; the working tree had untracked files only, so it was read as is, not pulled). Every constant comes from that repo, with file and line noted beside it: length-weight a and b per species (backend/app/core/config.py:40-41), cm per pixel and the 4 to 45 cm, 1.5 to 6 aspect gate (pond_config.yaml:37, 44-48), the stratified estimator's quality thresholds, 180-day cycle, 12% fallback mortality, 1.96 SE range, 30% single-fish fallback and 1.5x very-low widening (backend/app/biomass/biomass_estimator.py), and the feeding engine's size rates, temperature curve, feeding hours, response multipliers, minimum interval and feeds per day (backend/app/feeding/feeding_service.py). fixtures.json holds the outputs of the real Python functions (BiomassEngine, BiomassEstimator.estimate, BiomassHistory, PrecisionFeedingEngine) for 14 fixed input sets, made once with the repo's own venv by a throwaway script that was never committed. scripts/check-iris-sim.mjs compares the port with them (numbers within 0.5 percent, words exactly) and runs in npm run preflight after the filter check. Fixed label: "Simulation using the same formulas as the Iris software. Not field measurements." Left out because main does not compute them: keypoints (main runs the bounding-box model, length is the longer side of the box; the six-keypoint YOLO11-Pose pipeline is Spec 05, not built), ChArUco and depth calibration (Spec 06, not built; main uses a fixed scale), lucky-frame selection (Spec 07, not built; main runs the stratified estimator), and Oreochromis mossambicus (no profile in the code). The simulated camera sample (lengths from a seeded normal draw) is the only invented part and is marked as such in the code. Why: a visitor can see the reasoning, and every number traces to the code.
- **The sample chat plays itself on /projects/fishtech-sales-agent.** SalesAgentChatReplay shows typing dots, then each message, then the quotation PDF, starting when the phone is in view, with Pause and Replay. Under reduced motion the whole conversation shows at once and the buttons are not shown. Screen readers get the whole conversation once. Same text and "Sample conversation" label; the project card keeps the static chat. Why: the conversation is the product, and watching it arrive reads faster than a wall of bubbles.
- **Testimonials are built and hidden.** src/data/testimonials.ts (quote, name, role, organisation, project page, permission, permissionDate), seeded empty. The section sits after About and before Contact and renders only entries with permission true and a date; with none it renders nothing and stays out of the navbar and the footer. With one or more it is linked from the footer and the full-screen menu, not the crowded bar. Rule: a quote goes in only word for word, with written permission recorded with its date. Why: an empty or invented testimonial costs more trust than none.
- **Every screenshot folder is ignored.** .gitignore now ignores screenshots/** (it only ignored files directly in screenshots/, so round folders showed as untracked). Nothing under screenshots/ was tracked.
